## 中文

### 修复（v1.x 架构性问题，随本次重构整体消除）

#### 1. 接入必须修改客户端 Base URL 并经本地代理转发（多一跳网络层、多一处失效点）

- **根因**：v1.x（≤ 1.5.11）以本地反向代理（`127.0.0.1:8787`）作为唯一记账入口，客户端必须把 Base URL 指向代理（如 `http://127.0.0.1:8787/p/glm`），并在 `~/.stepfun-usage-monitor/providers.json` 按服务商覆盖 `baseUrl` / `apiKey`。多一跳进程意味着多一处失效点：代理未启动时，客户端全部请求直接失败；且客户端一旦升级模板或改配置，代理侧也要跟着改。
- **修复**：V2.0.0 废弃代理架构，改为**只读** ZCode 自带的 usage 数据库（默认 `~/.zcode/cli/db/db.sqlite`，可用 `ZCODE_USAGE_DB` 覆盖），不介入任何请求链路。
- **影响面**：安装插件即用，客户端零配置；v1.x 的 Base URL 绕行写法与 `providers.json` 全部不再需要；请求不再经过第三方进程，故障域收敛为 ZCode 自身。

#### 2. 速率展示滞后，「上轮」与「本轮」口径易混淆

- **根因**：v1.x 的速率行依赖模型在回答收尾时自行转发，或依赖请求入库后再采样——展示的经常是**上一条**回复的数据；对「模型→工具→模型」的多段轮次，更无法给出口径统一的即时速率。
- **修复**：注册 `Stop` 钩子，在回复结束、本轮全部请求已入库的瞬间，按最新 `turn_id` 圈定本轮全部请求（含多段），以「总产出 / 总纯生成时长」计算加权即时速率，经 `systemMessage` 由客户端**直接渲染**——不经过模型转发，从机制上消除滞后。
- **影响面**：回复结束即显示本轮数据；注入给模型的上一轮速率行降级为纯模型上下文，并明确禁止引用。

#### 3. 运行时依赖重，安装态与仓库代码易脱节

- **根因**：v1.x 需要 `npx` 从 GitHub 拉取运行时、外加 Python statusbar 常驻进程，插件安装态的 runtime 还需手工同步并逐字节校验。
- **修复**：全部实现为零依赖纯 `.mjs`（Node 内置 `node:sqlite` / `node:http`），插件安装即自包含；无常驻进程（监控大屏空闲 3 小时自退）。
- **影响面**：无 npm 依赖、无版本脱节问题；每个钩子单次运行都是一次毫秒级数据库只读。

### 新增功能

#### 1. 每轮即时速率行（Stop 钩子，默认开启）

- 每轮回复结束自动显示一行：本轮即时 tok/s、首字时间（TTFT）、输出 tokens、纯生成时长、请求段数 / 段内峰值、近几次滑动均值、会话累计输出、采样时刻。
- 速率分子纳入思考 token（`reasoning_tokens`），反映模型真实产出；多段轮次按「总产出 / 总纯生成时长」加权，剔除段间工具等待。
- 数字格式化：每轮「输出」用千分位精确数字（`2,762 tok`）；「累计」紧凑单位——千以下原始、1k~1万一位小数（`9.8k`）、1万~100万取整（`51k`）、≥100万一位小数（`73.8M`）。

#### 2. 实时监控大屏

- `/dashboard` 一键打开暗色运维风浏览器面板，每秒刷新；空闲 3 小时自动退出，不留后台进程；默认监听 `127.0.0.1:7423`。

#### 3. 斜杠命令

- `/tps` 即时快照；`/tps 10` 采样 10 秒（支持 2–30）；`/tps-doctor` 环境自检（Node 版本、usage 库表结构、最近样本时间、会话状态、配置文件、大屏进程），支持 `--json`，失败退出码 1。

#### 4. MCP 工具

- `tps_snapshot` / `tps_watch`：以标准 stdio MCP 服务器（`Content-Length` 帧，兼容裸 JSON 行请求）向 Agent 提供编程化访问；版本号自动读取 `plugin.json`，不与插件版本脱节。

#### 5. Windows 桌面悬浮条

- `dashboard/overlay.ps1` 把当前速率常驻为桌面文字悬浮层；macOS / Linux 用户可用大屏替代。

#### 6. 业务 TPS 监控（可选）

- 插件设置中配置 `metrics_url` 指向任意返回 JSON 的指标接口，字段名在三级嵌套内自适应（`tps`/`qps`/`throughput`/`transactionsPerSecond`、`p50`/`p95`/`p99`、`error_rate`/`errorRate`/`err_rate`）；未配置时使用内置演示数据。与 Token 速率相互独立——前者永远来自 ZCode 真实数据。

#### 7. 单元测试

- `node --test` 单元测试：数字换算（千分位 / 紧凑单位）、上一轮与本轮速率查询（含多段加权、旧库无 `turn_id` 列时优雅降级）、速率行文案、doctor 夹具环境，共 10 条断言。

## English

### Fixes (architectural issues of v1.x, eliminated by this rewrite)

#### 1. Setup required changing the client Base URL and routing through a local proxy (one extra network hop, one extra failure point)

- **Root cause**: v1.x (≤ 1.5.11) used a local reverse proxy (`127.0.0.1:8787`) as its only accounting entry point. Clients had to point their Base URL at the proxy (e.g. `http://127.0.0.1:8787/p/glm`) and override `baseUrl` / `apiKey` per provider in `~/.stepfun-usage-monitor/providers.json`. One extra process meant one extra failure point: when the proxy was down, every client request failed outright; and any client-side config change had to be mirrored on the proxy side.
- **Fix**: V2.0.0 discards the proxy architecture and **reads** ZCode's own usage database instead (default `~/.zcode/cli/db/db.sqlite`, overridable via `ZCODE_USAGE_DB`), staying out of the request path entirely.
- **Impact**: install the plugin and it just works — zero client configuration. The v1.x Base URL workaround and `providers.json` are no longer needed; requests no longer traverse a third-party process, shrinking the failure domain to ZCode itself.

#### 2. Rate display lagged, and the "previous turn" vs "current turn" distinction was easy to get wrong

- **Root cause**: v1.x rate lines relied on the model forwarding them at the end of its answer, or on sampling after requests were persisted — so what was shown was frequently the data of the **previous** reply. For multi-segment turns (model → tool → model) there was no way to report a unified instant rate.
- **Fix**: a `Stop` hook now fires the instant a reply ends and all of the turn's requests are persisted, scopes the turn by the latest `turn_id` (all requests of the turn, including multiple segments), computes a weighted instant rate as "total output / total pure generation time", and is rendered directly by the client via `systemMessage` — no model relay, eliminating the lag by construction.
- **Impact**: the current turn's data is shown the moment the reply ends; the injected previous-turn rate line is demoted to pure model context with an explicit prohibition on quoting it.

#### 3. Heavy runtime dependencies left the installed state easily out of sync with the repository

- **Root cause**: v1.x needed `npx` to fetch its runtime from GitHub plus a resident Python statusbar process, and the installed runtime had to be synced manually and verified byte-for-byte.
- **Fix**: everything is zero-dependency pure `.mjs` (Node built-ins `node:sqlite` / `node:http`), so the plugin is self-contained once installed; there is no resident process (the dashboard auto-exits after 3 idle hours).
- **Impact**: no npm dependencies and no version-skew problems; each hook run is a single millisecond-scale read-only database query.

### New Features

#### 1. Per-turn instant rate line (Stop hook, on by default)

- One line is shown automatically when each reply ends: instant tok/s for the turn, time to first token (TTFT), output tokens, pure generation time, request segments / per-segment peak, recent sliding average, session cumulative output, and sampling time.
- The rate numerator includes thinking tokens (`reasoning_tokens`), reflecting the model's true output; multi-segment turns are weighted by "total output / total pure generation time", excluding inter-segment tool waits.
- Number formatting: per-turn "output" uses exact thousands-separated numbers (`2,762 tok`); "total" uses compact units — raw below 1k, one decimal for 1k–10k (`9.8k`), rounded for 10k–1M (`51k`), one decimal M at or above 1M (`73.8M`).

#### 2. Real-time dashboard

- `/dashboard` opens a dark ops-style browser panel that refreshes every second; it auto-exits after 3 idle hours, leaving no background process; it listens on `127.0.0.1:7423` by default.

#### 3. Slash commands

- `/tps` for an instant snapshot; `/tps 10` to sample for 10 seconds (2–30 supported); `/tps-doctor` for environment self-checks (Node version, usage database table structure, most recent sample time, session state, config file, dashboard process), with `--json` support and exit code 1 on failure.

#### 4. MCP tools

- `tps_snapshot` / `tps_watch`: programmatic access for agents via a standard stdio MCP server (`Content-Length` frames, bare JSON-line requests also accepted); the version number is read from `plugin.json` automatically, so it never drifts from the plugin version.

#### 5. Windows desktop overlay

- `dashboard/overlay.ps1` keeps the current rate visible as a resident desktop text overlay; macOS / Linux users can use the dashboard instead.

#### 6. Business TPS monitoring (optional)

- Point `metrics_url` in the plugin settings at any endpoint returning JSON; field names are auto-matched within three nesting levels (`tps`/`qps`/`throughput`/`transactionsPerSecond`, `p50`/`p95`/`p99`, `error_rate`/`errorRate`/`err_rate`). Built-in demo data is used when unconfigured. It is independent of the token rate — the latter always comes from real ZCode data.

#### 7. Unit tests

- `node --test` unit tests: number formatting (thousands separators / compact units), previous-turn and current-turn rate queries (including multi-segment weighting and graceful degradation when an old database lacks the `turn_id` column), rate-line copy, and doctor fixture environments — 10 assertions in total.
