## 中文

### 新增功能

#### 1. 外观配置节（`~/.zcode/tps-monitor.config.json`）

在既有 `stopHookLine` / `tokenRateLine` 同级新增 `appearance` 节，**只增不删**——旧配置文件没有任何该节时，行为与 V2.0.0 完全一致：

| 字段 | 类型 / 取值 | 默认 | 说明 |
| --- | --- | --- | --- |
| `theme` | `dark` / `light` / `system` | `dark` | `system` 跟随系统深浅色偏好 |
| `fontFamily` | CSS 字体栈 | `Segoe UI, Microsoft YaHei, system-ui, sans-serif` | 界面字体 |
| `monoFont` | CSS 字体栈 | `Cascadia Mono, Consolas, monospace` | 数字 / 时钟字体 |
| `fontSize` | 8–24（数字） | `16` | 基准字号（px） |
| `fontScale` | 0.8–1.5（数字） | `1` | 整体缩放倍率 |
| `accentColor` | `#hex` / `rgb(a)` / `hsl(a)` / 常用英文色名 | `#4da3ff` | 主题色 |
| `glassIntensity` | 0–1（数字） | `0.6` | 液态玻璃强度，`0` 为完全关闭 |
| `fontUrl` | `http(s)://` 或 `file://` URL | 空 | 可选 Web 字体，加载失败静默回退系统字体栈 |

数值越界会被夹紧到合法区间（如 `fontSize: 99` → `24`），非法值（类型错误、注入字符、非法颜色 / 协议）整条补写被拒绝并返回字段级错误，**不落盘**；配置文件损坏（JSON 语法错误）时抛出带修复提示的错误，绝不静默覆盖。

#### 2. 配置读写 API

- `GET /api/config`：返回当前 `appearance`、既有配置字段与配置文件绝对路径。
- `POST /api/config`：请求体 `{"appearance": {…}}`，逐字段校验后**合并写入**（只改 `appearance` 节，`stopHookLine` 等旧字段原样保留）；非法字段返回 `400` + `fieldErrors`；其他方法返回 `405`。

#### 3. 页内设置抽屉

- 大屏右上角「⚙ 外观」打开右侧抽屉：主题、界面字体、数字字体、基准字号、整体缩放、主题色（取色器 + 文本双向同步）、玻璃强度、Web 字体 URL。
- 保存后即时生效并持久化；打开抽屉时会重新拉取一次配置，与 CLI 等其他端的写入保持一致。
- 字体类输入框留空表示「用默认值」，与「重置」语义一致。

#### 4. Web 字体动态加载

- `fontUrl` 指向的字体文件经 `FontFace` API 异步加载，成功后作为最高优先级插入字体栈；任何失败（网络错误、格式错误）都静默回退系统字体栈，不阻塞首屏。

#### 5. Windows 悬浮条外观对齐

- `overlay.ps1` 读取同一 `appearance` 节：按 `fontFamily` / `monoFont` 映射 WPF 可用字体（自动剔除 `system-ui` 等 CSS 专有族名），字号按 `fontSize × fontScale` 计算。
- `glassIntensity > 0` 时尝试启用 Acrylic 背景（按主题选用深 / 浅着色）；底层窗口合成失败时静默回退 V2.0.0 的透明纯文本形态。

#### 6. doctor 外观自检

- `/tps-doctor` 新增「外观配置」检查项：配置文件缺失为**提示项**（默认外观，不计失败）；JSON 损坏或字段非法为**失败项**，附修复建议；`fontUrl` 可达性仅作提示，3 秒超时，任何情况下不阻断自检。

### 液态玻璃与主题

- 大屏样式全面 CSS 变量化：主题色、字体、字号、缩放、玻璃参数全部由配置驱动，`html` 根字号 = `fontSize × fontScale`，卡片 / 面板 / 图表统一使用 rem 与 CSS 变量，切换主题无需刷新页面。
- 默认 `glassIntensity: 0.6`：半透明面板底 + `backdrop-filter: blur() saturate()` + 内侧高光边 + 多层投影，呈现液态玻璃质感。
- 不支持 `backdrop-filter` 的环境（`@supports` 命中）自动降级为实色面板，不影响可读性。
- `glassIntensity: 0` 时 `data-glass="off"`，完全恢复 V2.0.0 的实色配色与 12px（0.75rem）圆角。
- 速率曲线与系统图表的颜色 / 字体改读 CSS 变量，跟随主题与主题色联动；非 hex 主题色不再拼接 alpha 通道，避免渐变色错误。

### 安全

- **字体栈字符白名单**：仅允许字体名、逗号、引号、连字符等安全字符，拒绝 `; { } < > ( ) \` 等可破坏 CSS 的字符——注入式字体栈无法进入配置。
- **颜色格式校验**：仅接受 `#hex`（3/4/6/8 位）、`rgb()` / `rgba()` / `hsl()` / `hsla()` 与常用英文色名。
- **字体 URL 协议白名单**：仅 `http:` / `https:` / `file:`，拒绝 `javascript:` 等危险协议。
- 配置在**服务端注入**页面（`window.__TPS_CONFIG__`，首屏绘制前生效），彻底消除主题闪烁；`file://` 直开时回退为客户端拉取。数据全部本地，无任何网络上报。

### 版本

- 新增零依赖共享模块 `scripts/lib/config.mjs`：大屏服务、doctor 与单元测试共用同一套校验逻辑（core 仍保持零 npm 依赖）。
- `marketplace.json`、`.zcode-plugin/plugin.json`、`.claude-plugin/plugin.json` 统一升级为 **2.1.0**。
- 单元测试扩充至 **26** 条（新增外观校验 / 合并写 / 损坏修复 / doctor 外观检查等 16 条）。
- README（中 / 英）补充外观配置字段表与 `scripts/lib/config.mjs` 目录说明。

## English

### New Features

#### 1. Appearance config section (`~/.zcode/tps-monitor.config.json`)

A new `appearance` section sits alongside the existing `stopHookLine` / `tokenRateLine` fields and is **additive only** — an old config file without it behaves exactly as in V2.0.0:

| Field | Type / values | Default | Notes |
| --- | --- | --- | --- |
| `theme` | `dark` / `light` / `system` | `dark` | `system` follows the OS light/dark preference |
| `fontFamily` | CSS font stack | `Segoe UI, Microsoft YaHei, system-ui, sans-serif` | UI font |
| `monoFont` | CSS font stack | `Cascadia Mono, Consolas, monospace` | Numeric / clock font |
| `fontSize` | 8–24 (number) | `16` | Base font size (px) |
| `fontScale` | 0.8–1.5 (number) | `1` | Overall scale factor |
| `accentColor` | `#hex` / `rgb(a)` / `hsl(a)` / common CSS color name | `#4da3ff` | Accent color |
| `glassIntensity` | 0–1 (number) | `0.6` | Liquid glass strength; `0` disables it entirely |
| `fontUrl` | `http(s)://` or `file://` URL | empty | Optional web font; silently falls back to the system font stack on failure |

Out-of-range numbers are clamped into the legal range (e.g. `fontSize: 99` → `24`), while illegal values (wrong types, injection characters, invalid colors / protocols) reject the whole patch with field-level errors and **nothing is written to disk**. A corrupt config file (invalid JSON syntax) throws an error with a repair hint and is never silently overwritten.

#### 2. Config read/write API

- `GET /api/config`: returns the current `appearance`, the existing config fields, and the absolute config file path.
- `POST /api/config`: body `{"appearance": {…}}`, validated field by field and then **merged** into the file (only the `appearance` section changes; `stopHookLine` and friends are preserved verbatim). Illegal fields return `400` with `fieldErrors`; other methods return `405`.

#### 3. In-page settings drawer

- The "⚙ 外观" button in the dashboard header opens a side drawer: theme, UI font, numeric font, base font size, overall scale, accent color (color picker + text field kept in sync), glass intensity, and web font URL.
- Saving applies immediately and persists; opening the drawer re-fetches the config once so it stays consistent with writes from other surfaces such as the CLI.
- Leaving a font field empty means "use the default value", matching the reset semantics.

#### 4. Dynamic web font loading

- The font at `fontUrl` is loaded asynchronously via the `FontFace` API and, on success, is prepended to the font stack as the highest-priority family. Any failure (network error, bad format) silently falls back to the system font stack without blocking first paint.

#### 5. Windows overlay appearance alignment

- `overlay.ps1` reads the same `appearance` section: `fontFamily` / `monoFont` are mapped to WPF-usable fonts (CSS-only families such as `system-ui` are filtered out automatically), and the font size is computed as `fontSize × fontScale`.
- When `glassIntensity > 0`, Acrylic is attempted (dark / light tint chosen by theme); if the underlying window composition fails, it silently falls back to the V2.0.0 transparent text-only form.

#### 6. Doctor appearance self-check

- `/tps-doctor` gains an "appearance config" check: a missing config file is a **hint** (defaults in use, not a failure); corrupt JSON or illegal fields are **failures** with repair hints; `fontUrl` reachability is hint-only with a 3-second timeout and never blocks the check.

### Liquid glass and theming

- The dashboard stylesheet is fully CSS-variable driven: accent color, fonts, font size, scale, and glass parameters all come from config, with `html` root font size = `fontSize × fontScale`; cards, panels, and charts all use rem units and CSS variables, so switching themes needs no page reload.
- Default `glassIntensity: 0.6`: translucent panel background + `backdrop-filter: blur() saturate()` + inset highlight edge + multi-layer shadow for a liquid-glass look.
- Environments without `backdrop-filter` support (matched via `@supports`) automatically degrade to solid panels with no loss of readability.
- With `glassIntensity: 0`, `data-glass="off"` fully restores V2.0.0's solid palette and 12px (0.75rem) corner radius.
- Rate-curve and system-chart colors / fonts now read CSS variables, so they follow theme and accent changes; non-hex accent colors no longer concatenate an alpha channel, avoiding broken gradients.

### Security

- **Font-stack character whitelist**: only font names, commas, quotes, hyphens and similar safe characters are allowed; `; { } < > ( ) \` and other CSS-breaking characters are rejected, so an injected font stack can never enter the config.
- **Color format validation**: only `#hex` (3/4/6/8 digits), `rgb()` / `rgba()` / `hsl()` / `hsla()`, and common CSS color names are accepted.
- **Font URL protocol whitelist**: only `http:` / `https:` / `file:`; dangerous protocols such as `javascript:` are rejected.
- The config is injected **server-side** into the page (`window.__TPS_CONFIG__`, applied before first paint), eliminating theme flash entirely; when the page is opened via `file://` it falls back to a client-side fetch. All data stays local — nothing is ever reported over the network.

### Version

- New zero-dependency shared module `scripts/lib/config.mjs`: the dashboard server, doctor, and unit tests all share one validation implementation (the core still has zero npm dependencies).
- `marketplace.json`, `.zcode-plugin/plugin.json` and `.claude-plugin/plugin.json` all bumped to **2.1.0**.
- Unit tests expanded to **26** (16 new: appearance validation, merge-write, corruption repair, doctor appearance checks).
- README (Chinese / English) gains the appearance config field table and a `scripts/lib/config.mjs` entry in the directory layout.
