## 中文

V2.3.0 之后，插件已经能读 ZCode 自己的 usage 库、跑 Electron 桌面端。V2.4.0 解决的是下一个问题：**同样一套「本轮即时 tok/s」的口径，能不能覆盖其他客户端工具？**

答案是能，但前提是把「读 ZCode 库」这件事从插件各处抽出来，变成一个**统一的 Provider 接口**。本版只做**数据层与命令层**——多 agent 的聚合展示 UI 是 V2.5.0 的范围。

硬约束从头到尾没松：插件核心（hooks / scripts / mcp / commands / dashboard）**零 npm 依赖、纯 Node ≥ 22.5**，全部只读本地文件、不联网、无遥测，配置字段只增不删。**默认 `providers = ["zcode"]` 时，速率行 / 命令 / 大屏 / MCP 的输出与 V2.3.0 完全一致**（只多一个 `provider` 字段）。

### 架构：一个接口，五个数据源

```text
scripts/lib/providers/
├─ index.mjs        注册表:ID / 别名 / 能力矩阵 / 归一化 / 按配置取源
├─ common.mjs       归一化与视图构建(速率公式与 usage-db 同源)
├─ zcode.mjs        ~/.zcode/cli/db/db.sqlite · model_usage 表(原样迁入)
├─ claude-code.mjs  ~/.claude/projects/**/*.jsonl 会话日志
├─ codex.mjs        ~/.codex/sessions/ rollout 记录
├─ opencode.mjs     ~/.local/share/opencode/storage/message/…
└─ cline.mjs        <编辑器 globalStorage>/tasks/*/…
```

每个 Provider 对外只承诺三件事：

| 成员 | 作用 |
| --- | --- |
| `id` / `label` | 稳定标识与展示名（`"zcode"` / `"claude-code"` / `"codex"` / `"opencode"` / `"cline"`） |
| `capabilities` | 能力声明：`turnRate` / `ttft` / `sessionScope`，UI 与命令按能力降级 |
| `detect()` / `listSessions()` / `getUsage()` | 探测、列会话、取归一化记录 |

归一化记录统一为 `tokens / 时间 / 模型 / turnKey` 四类字段。上游各客户端的字段名千差万别（`output_tokens` / `outputTokens` / `tokensOut` / `completion_tokens`…），这些差异全部收口在 Provider 内部，**聚合层只认归一化后的记录**。

#### 能力矩阵：不记录就是不记录

四个第三方客户端都不落首 token 时刻，因此它们的 `capabilities.ttft` 一律为 `false`，`ttftMs` 恒为 `null`。UI 与命令据此显示 `-`，**不拿相邻请求差去冒充首字延迟**——估算值和实测值混在一个字段里，比空值更难排查。

| 数据源 | turnRate | ttft | sessionScope | 数据格式 |
| --- | --- | --- | --- | --- |
| `zcode` | ✅ | ✅ | ✅ | sqlite / model_usage |
| `claude-code` | ✅ | ❌ | ✅ | jsonl / projects |
| `codex` | ✅ | ❌ | ✅ | jsonl / sessions |
| `opencode` | ✅ | ❌ | ✅ | json / storage.message |
| `cline` | ✅ | ❌ | ✅ | json / tasks |

### 聚合查询层：单源走原路，多源才合并

`scripts/lib/collect-core.mjs` 新增 `aggregateRate` / `aggregateTurn` / `agentStatus` 三个入口，`scripts/token-rate.mjs` 的 `query` / `queryTurn` 直接委托过去。这一个改动就让**大屏、Electron 悬浮条、CLI、MCP 同时切换到聚合层**，无需逐处改代码。

关键是单源时不背多源的开销：

```js
isFastPath(ids) = ids.length === 1 && ids[0] === "zcode"
```

命中时直接 `createProvider("zcode").rate()` → `openUsageDb(dbPath).query()`，也就是 V2.3.0 那条代码路径原样执行，**只在结果上多一个 `provider` 字段**，`sources` / `agents` 压根不出现。测试用 `deepEqual` 逐字段比对：剥掉 `provider` 后与 `openUsageDb().query()` 完全一致。

多源时按完成时刻排序合并（并列时按 `providers` 里的声明顺序，保证可复现），窗口统计与累计统计跨源求和，并附上 `sources`（每源探测结果与样本数）与 `agents`（能力矩阵）两份明细。

### 生成耗时：四个源的四种口径

这是本版最容易出错的地方。ZCode 库直接落 `first_token_at` / `completed_at`，是实测；其他客户端没有这两个字段，只能估算，且各自能拿到的东西不一样：

| 数据源 | 口径 | 说明 |
| --- | --- | --- |
| `zcode` | `completed_at - first_token_at` | 实测，原样不变 |
| `claude-code` | 相邻请求时间差 | 超过 120s 视为中间夹了人工思考，判为无效 |
| `codex` | `token_count` 事件间隔 | 旧版只给累计值时按差分求单次增量，累计值回退自动识别 reset |
| `opencode` | 客户端自记的 `created` / `completed` | 最接近实测的一个 |
| `cline` | 相邻请求差 | 与任意条目比对，不限有用例的条目 |

**这些估算值之间不可直接横向比较**，与 ZCode 的实测值也不可比。README 的「多 agent 支持」一节把这点写明了。

### 故障隔离：一个源坏了，不连累其他人

`aggregateRate` 对每个源单独 try/catch：某个源读失败，只在 `sources` 里给它记一条 `{ ok: false, reason: "数据读取失败: …" }`，其余源照常出数；未安装的客户端在 `detect()` 就被跳过，连读都不读。

doctor 的「数据源(多 agent)」检查项按同一套口径逐源给结论：**可用/不可用 + 原因 + 数据格式 + 样本条数**。已安装但本地还没有数据的源只提示、不算自检失败——聚合层本来就会跳过它，插件其余功能不受影响。

顺带修了一个真问题：`dbCheck` 原来只兜住了「打不开」，没兜住「打不开之后的第一次 `prepare`」。文件被截断或不是 SQLite 时，`/tps-doctor` 会整个崩掉、一份报告都出不来。现在它返回失败项并给出修复提示。

### 钩子热路径：JSONL 一律不进

Stop / prompt-submit 钩子**直连 zcode usage 库**，不经聚合层。这不是巧合而是设计：JSONL 是可能到几十 MB 的文件，逐条解析进钩子热路径会顶破 50ms 预算。因此即使 `providers` 配满五个源，钩子输出与只用 zcode 时**逐字节相同**。

测试用一个「毒药」夹具守着这条线：一份时间戳远在未来、token 数独一无二的 Claude Code 数据，先证明聚合层确实读得到它（否则测试没有牙齿），再证明钩子对它无感、输出数值一模一样。

### Electron 与大屏：零改动切换

悬浮条与大屏都经 `scripts/token-rate.mjs` 取数，而该模块现在就是聚合层——所以桌面端自动获得多源能力，没有为它写一行专用代码。内嵌服务仍绑 127.0.0.1、随机端口、不写 PID、不空闲退出。

大屏 `/api/config` 新增 `providers` 字段的读写（与 `appearance` 相互独立，只传一段也能用）；SSE 快照的 `token` 载荷带上 `provider`，多源时才附 `sources` / `agents`。

### MCP：只增字段，不改名

`tps_snapshot` / `tps_watch` 的结果新增 `provider` 与 `sessionId`。工具名、`content`、`isError` 原样保留，老客户端忽略新字段时行为与 V2.3.0 完全一致。

### 安全与兼容

- 插件核心**零新增 npm 依赖**，Provider 全部纯 Node 实现（`node:fs` / `node:path` / `node:os` / `node:sqlite`）。
- 全部只读本地文件：不联网、无遥测、不上报任何数据。各源的数据根目录都可用环境变量覆盖（`TPS_CLAUDE_CODE_HOME` / `TPS_CODEX_HOME` / `TPS_OPENCODE_HOME` / `TPS_CLINE_HOME`），默认走各客户端的官方位置。
- 配置字段**只增不删**：不写 `providers` 时默认 `["zcode"]`，旧配置文件行为与 V2.3.0 一致；未知 ID 在归一化时被丢弃并回退默认值，不会让插件起不来。
- MCP 返回结构**只增字段**；JSONL 解析带单行故障隔离与 2 万条上限，坏行只跳过自己。

## English

After V2.3.0, the plugin could read ZCode's own usage DB and run on Electron. V2.4.0 tackles the next question: **can the same "instant tok/s of this turn" measure cover other client tools?**

It can — but only if "read the ZCode DB" is first pulled out of every call site into a **unified Provider interface**. This release ships the **data and command layers only**; the multi-agent aggregation UI is V2.5.0's scope.

The hard constraints never moved: the plugin core (hooks / scripts / mcp / commands / dashboard) keeps **zero npm dependencies and pure Node ≥ 22.5**, reads local files only, never touches the network, and only ever adds config fields. **With the default `providers = ["zcode"]`, the rate line, commands, dashboard and MCP output are identical to V2.3.0** — one extra `provider` field aside.

### Architecture: one interface, five sources

```text
scripts/lib/providers/
├─ index.mjs        Registry: ids / aliases / capability matrix / normalization / source selection
├─ common.mjs       Normalization and view building (rate formula shared with usage-db)
├─ zcode.mjs        ~/.zcode/cli/db/db.sqlite · model_usage table (migrated verbatim)
├─ claude-code.mjs  ~/.claude/projects/**/*.jsonl session logs
├─ codex.mjs        ~/.codex/sessions/ rollout records
├─ opencode.mjs     ~/.local/share/opencode/storage/message/…
└─ cline.mjs        <editor globalStorage>/tasks/*/…
```

Each Provider promises only three things:

| Member | Purpose |
| --- | --- |
| `id` / `label` | Stable identifier and display name (`"zcode"` / `"claude-code"` / `"codex"` / `"opencode"` / `"cline"`) |
| `capabilities` | Declared capabilities: `turnRate` / `ttft` / `sessionScope`; UI and commands degrade accordingly |
| `detect()` / `listSessions()` / `getUsage()` | Probe, list sessions, fetch normalized records |

Normalized records use exactly four field groups: `tokens / time / model / turnKey`. Upstream field names vary wildly (`output_tokens` / `outputTokens` / `tokensOut` / `completion_tokens`…); all of that is contained inside the Provider, and **the aggregation layer only ever sees normalized records**.

#### Capability matrix: absent means absent

None of the four third-party clients record a first-token timestamp, so their `capabilities.ttft` is `false` and `ttftMs` is always `null`. The UI and commands render `-` rather than **passing off an inter-request gap as a first-token delay** — mixing estimates into a field that holds measurements is harder to debug than an empty value.

| Source | turnRate | ttft | sessionScope | Format |
| --- | --- | --- | --- | --- |
| `zcode` | ✅ | ✅ | ✅ | sqlite / model_usage |
| `claude-code` | ✅ | ❌ | ✅ | jsonl / projects |
| `codex` | ✅ | ❌ | ✅ | jsonl / sessions |
| `opencode` | ✅ | ❌ | ✅ | json / storage.message |
| `cline` | ✅ | ❌ | ✅ | json / tasks |

### Aggregation layer: original path for one source, merge only for many

`scripts/lib/collect-core.mjs` gains `aggregateRate` / `aggregateTurn` / `agentStatus`, and `scripts/token-rate.mjs`'s `query` / `queryTurn` delegate to them. That single change moves **the dashboard, the Electron overlay, the CLI and MCP onto the aggregate layer at once**, with no per-call-site edits.

The important part is that one source pays nothing:

```js
isFastPath(ids) = ids.length === 1 && ids[0] === "zcode"
```

On a hit it goes straight to `createProvider("zcode").rate()` → `openUsageDb(dbPath).query()` — literally the V2.3.0 code path, **with one extra `provider` key on the result**; `sources` and `agents` are not present at all. A test compares field by field: strip `provider` and the object deep-equals `openUsageDb().query()`.

With multiple sources, records are merged in descending completion order (ties broken by declaration order in `providers`, so results are reproducible), window and cumulative statistics sum across sources, and two detail blocks are attached: `sources` (per-source probe result and sample count) and `agents` (capability matrix).

### Generation time: four sources, four definitions

This is where the release could most easily have gone wrong. The ZCode DB stores `first_token_at` / `completed_at` directly — measured. The other clients have neither field, so their durations are estimates, and each has different raw material:

| Source | Definition | Notes |
| --- | --- | --- |
| `zcode` | `completed_at - first_token_at` | Measured, unchanged |
| `claude-code` | Gap to the previous request | Gaps over 120s are treated as human thinking time and rejected |
| `codex` | Interval between `token_count` events | Older builds only report cumulative totals; per-request deltas are derived, with reset detection |
| `opencode` | Client-recorded `created` / `completed` | The closest to a real measurement |
| `cline` | Gap to the previous entry | Compared against any entry, not only ones carrying usage |

**These estimates are not directly comparable to each other**, nor to ZCode's measured values. The README's "Multi-agent support" section states this explicitly.

### Fault isolation: one broken source doesn't take the rest down

`aggregateRate` wraps each source in its own try/catch: if a source fails to read, it gets a `{ ok: false, reason: "数据读取失败: …" }` entry in `sources` and the other sources carry on; a client that isn't installed is skipped at `detect()` and never read.

doctor's "数据源(多 agent)" check follows the same convention per source: **available / unavailable + reason + data format + sample count**. A source that is installed but has no local data yet is informational, not a failure — the aggregation layer skips it anyway and the rest of the plugin is unaffected.

One genuine bug got fixed along the way: `dbCheck` used to catch "cannot open" but not "the first `prepare` after opening". On a truncated or non-SQLite file, `/tps-doctor` crashed and produced no report at all. It now returns a failed item with a repair hint.

### Hook hot path: JSONL stays out

The Stop and prompt-submit hooks **talk to the zcode usage DB directly** and never go through the aggregation layer. That is deliberate, not accidental: JSONL files can reach tens of megabytes, and parsing them in the hook hot path would blow the 50ms budget. So even with all five sources configured, the hook output is **byte-identical** to a zcode-only setup.

A "poison" fixture guards that line: Claude Code data with timestamps far in the future and unmistakable token counts. The test first proves the aggregate layer really does read it (otherwise the test has no teeth), then proves the hooks are blind to it and emit the exact same numbers.

### Electron and dashboard: switched with zero code changes

Both the overlay and the dashboard fetch data through `scripts/token-rate.mjs`, which is now the aggregate layer — so the desktop client gains multi-source support without a single line of dedicated code. The embedded server still binds 127.0.0.1 on a random port, writes no PID file and never idle-exits.

The dashboard's `/api/config` gains read/write for `providers` (independent of `appearance`; either section alone is enough), and the SSE `token` payload carries `provider`, with `sources` / `agents` attached only when multiple sources are enabled.

### MCP: additive fields only

`tps_snapshot` and `tps_watch` gain `provider` and `sessionId`. Tool names, `content` and `isError` are untouched, so older clients that ignore the new fields behave exactly as they did in V2.3.0.

### Security and compatibility

- **Zero new npm dependencies** in the plugin core; every Provider is pure Node (`node:fs` / `node:path` / `node:os` / `node:sqlite`).
- Local files only: no network, no telemetry, nothing reported anywhere. Each source's data root can be overridden by environment variable (`TPS_CLAUDE_CODE_HOME` / `TPS_CODEX_HOME` / `TPS_OPENCODE_HOME` / `TPS_CLINE_HOME`), defaulting to each client's official location.
- Config fields are **additive only**: with no `providers` written the default is `["zcode"]`, and an old config file behaves exactly as in V2.3.0. Unknown ids are dropped during normalization with a fallback to the default, so a typo can't stop the plugin from starting.
- MCP return structures are **additive only**; JSONL parsing has per-line fault isolation and a 20,000-record cap, so a bad line only skips itself.
