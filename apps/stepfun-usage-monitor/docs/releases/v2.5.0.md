## 中文

V2.4.0 把五个数据源接进了聚合层,但展示仍是单 agent 视图。V2.5.0 补齐最后一层:**大屏、Electron 悬浮条、托盘与 `/tps` 输出同时展示多个 agent**,支持切换与对比。数据层除 `agentStatus` 补一个 `sessionList` 字段外不再改动。

硬约束不变:**默认 `providers=["zcode"]` 时新 UI 元素一律不出现**,大屏/命令/悬浮条输出与 V2.4.0 完全一致;插件核心零 npm 依赖,大屏纯 CSS + 原生 JS,无构建工具;配置字段只增不删;数据全本地。

### 大屏:切换条 + 分组卡片

header 下方新增**数据源切换条**——「全部 / ZCode / Claude Code / Codex / OpenCode / Cline」胶囊条,数据来自新端点 `GET /api/agents`(逐源探测:标签、能力、格式、可用性、当前会话、会话列表)。三点设计:

- **能力降级**:每 provider 一张「速率 / 首字 / 输出 / 请求」卡片;第三方源没有首 token 时刻,首字段显示**「—」**而不是编数字——估算值混进实测字段比空值更难排查。
- **聚焦语义**:点击某源即聚焦,对比曲线中其余变淡、卡片描边高亮;焦点存 localStorage(刷新/重启保留),指向的源被移除时自动回落「全部」。
- **单源即隐身**:启用源 ≤ 1 时切换条与整个多 agent 区块不渲染,页面与 V2.4.0 逐像素一致。

### 对比视图:同轴多曲线 + 口径图例

新增「多 agent 对比 · 同轴速率」面板:每个启用源一条速率曲线,**同轴叠加**(复用现有 canvas 绘制函数,扩展了按 series 淡化能力),图例标注口径差异——ZCode 标「实测口径」,第三方源标「估算口径」。重绘仍走脏标记 + rAF:空闲零轮询,多曲线稳态只随新样本推进。

数据通路:快照携带 `perProvider`(各源自己的当前会话视图,含历史)作为起点;此后每源的新样本经带 `provider` 字段的 `history-append` 增量推进;`token` 事件附 `perProvider` 的 latest/session(不带历史,稳态增量保持精悍)。单源时这些字段与事件一律不出现。

### 会话切换器

同一工具存在多个会话时,分组卡片内出现会话下拉:单选聚焦(该源卡片与对比曲线改用 REST 一次性快照,**不新增轮询**)或跟随当前会话;每个源的记忆独立存 localStorage。数据来自 `/api/agents` 的 `sessionList`——这是 V2.5.0 对数据层的唯一补齐(探测时顺手保留已有列表,不产生额外读取)。

### Electron 与悬浮条:聚焦数据源

新配置字段 **`focusAgent`**(缺省 `zcode`,`"all"` = 聚合全部启用源):

- **托盘菜单**新增「聚焦数据源」子菜单(单选,标注各源可用性),写入配置即刻生效——悬浮条采集循环每次采集都现读该字段。
- **Electron 悬浮条**聚焦非 zcode 源时显示来源标签,展开详情多一行「数据源」;缺省 zcode 时视觉与 V2.4.0 一致。
- **overlay.ps1** 读同一份配置:轮询 URL 追加 `?agent=<id>`,统计行前缀来源名;不配置时 URL 与 V2.4.0 逐字节一致。

聚焦 zcode(缺省)时查询结果与 V2.4.0 的合并查询完全一致——默认 providers 配置下,悬浮条行为逐字节不变。

### `/tps` 聚合输出

多源时人类可读输出新增「各源速率:」块,按数据源分组给出各自速率/首字/输出/请求数;单源损坏只让它自己那行显示读取失败,其余照常。`--json` 多源时附 `perProvider` 字段(只增不改)。缺省单 zcode 不打印这些块。

一个口径说明:**分组卡片与对比曲线是各源"自己的当前会话"**,顶部主卡片仍是 followed 会话口径(会话 id 跨工具不通用,不能借用)——两处横向不可比,这是多工具场景的固有属性而非缺陷。

### 接口增补(全部 additive)

| 接口 | 增补 |
| --- | --- |
| `GET /api/agents` | 新端点:启用清单 + 逐源探测 + 会话列表 |

## English

V2.4.0 wired five data sources into the aggregation layer, but the display remained single-agent. V2.5.0 completes the last layer: **the dashboard, the Electron overlay, the tray and `/tps` output now show multiple agents at once**, with switching and comparison. The data layer is untouched except for one `sessionList` field on `agentStatus`.

The hard constraints hold: **with the default `providers=["zcode"]` none of the new UI appears**, and dashboard/commands/overlay output is identical to V2.4.0; the plugin core keeps zero npm dependencies, the dashboard is pure CSS + vanilla JS with no build step; config fields are additive only; all data stays local.

### Dashboard: switcher bar + grouped cards

A **source switcher bar** appears under the header — "全部 / ZCode / Claude Code / Codex / OpenCode / Cline" chips fed by the new `GET /api/agents` endpoint (per-source probe: label, capabilities, format, availability, current session, session list). Three design points:

- **Capability degradation**: one "rate / TTFT / output / requests" card per provider; third-party sources record no first-token moment, so the TTFT field renders **"—"** rather than a fabricated number — mixing estimates into measured fields is harder to debug than an empty value.
- **Focus semantics**: clicking a source focuses it — the other curves dim and the card gets an accent border; the focus lives in localStorage (survives reloads) and falls back to "全部" when the focused source disappears.
- **Invisible when single-source**: with ≤ 1 enabled source neither the bar nor the multi-agent section renders; the page is pixel-identical to V2.4.0.

### Comparison view: same-axis curves + caliber legend

A new "多 agent 对比 · 同轴速率" panel overlays one rate curve per enabled source on the **same axes** (reusing the existing canvas painter, extended with per-series dimming); the legend marks caliber differences — ZCode says "实测口径" (measured), third-party sources say "估算口径" (estimated). Redraws still go through the dirty-flag + rAF path: zero polling when idle, steady-state multi-curve CPU only advances on new samples.

Data path: the snapshot carries `perProvider` (each source's own current-session view, with history) as the starting point; afterwards each source's new samples arrive as `history-append` events tagged with a `provider` field; the `token` event carries each source's latest/session without history so steady-state increments stay small. None of these appear for single-source setups.

### Session switcher

When a tool has multiple sessions, each card gains a session dropdown: pick one to focus (that source's card and comparison curve switch to a one-shot REST snapshot — **no new polling**) or follow the current session; each source's choice is remembered in localStorage. The data comes from `sessionList` on `/api/agents` — the only data-layer addition in this release (the probe already had the list; it is now kept, no extra reads).

### Electron and the overlay: focusAgent

A new config field **`focusAgent`** (default `zcode`, `"all"` = aggregate every enabled source):

- The **tray menu** gains a "聚焦数据源" radio submenu (annotated with availability); writing the config takes effect immediately — the overlay collection loop re-reads the field on every tick.
- The **Electron overlay** shows a source tag when a non-zcode source is focused, plus a "数据源" row in the expanded details; with the default zcode focus the visuals match V2.4.0.
- **overlay.ps1** reads the same config: the polled URL gains `?agent=<id>` and the stats line gains a source prefix; unconfigured, its URL is byte-identical to V2.4.0.

Focusing zcode (the default) yields exactly what the V2.4.0 merged query produced — on the default providers config the overlay is byte-identical.

### `/tps` aggregated output

With multiple sources, the human-readable output gains a "各源速率:" block listing each source's rate/TTFT/output/requests; a broken source only fails its own line. `--json` carries `perProvider` (additive). With the default single zcode source none of these blocks are printed.

One caliber note: **the grouped cards and comparison curves reflect each source's own current session**, while the top summary card remains the followed-session caliber (session ids don't transfer across tools) — the two are not comparable across sources; that is inherent to the multi-tool scenario, not a defect.

### Interface additions (all additive)

| Interface | Addition |
| --- | --- |
| `GET /api/agents` | New endpoint: enabled list + per-source probe + session list |
| SSE `agents` event | Pushed when the source list changes (including multi → single); also sent on multi-source connect |
| SSE `snapshot` / `token` | `perProvider` when multi-source; single-source structure unchanged |
| SSE `history-append` | Per-source increments carry `provider` when multi-source; single-source semantics frozen |
| `GET /api/token-rate` | Optional `?agent=` (unknown source → 400) / `?session=` |
| `GET/POST /api/config` | `focusAgent` field (default zcode) |
| `agentStatus()` | `sessionList` (≤ 10 entries) |

### Security and compatibility

- Zero new dependencies in the plugin core; the dashboard is pure CSS + vanilla JS, and `node --test` still statically asserts the desktop buttons stay hidden in browsers.
- Config fields are additive only: an old config without `focusAgent` falls back to `zcode`; illegal values are rejected by `/api/config` (400 + fieldErrors) without touching the file.
- SSE legacy event semantics are frozen: provider-tagged increments only appear in multi-source mode; older front-mends consuming the existing fields are unaffected.
- All data stays local: switching, focusing and session enumeration only ever read local files.
