## 中文

V2.1.0 把大屏做成了可定制的液态玻璃面板，V2.2.0 在此基础上消除三类固定开销——**通信层的无效轮询、渲染层的全量重绘、数据层的低效 SQL**。所有优化都发生在既有渲染管线内部：钩子的速率计算逻辑与输出格式一字未改，`/tps`、`/tps-doctor` 的行为不变（仅 `doctor --json` 新增 perf 节），MCP 返回结构不变，配置字段只增不删。

### 通信层：SSE 推送取代定时轮询

#### 1. `GET /api/events`

新增 SSE 端点，纯 `node:http` 实现，**零第三方依赖**：

```text
GET /api/events
Content-Type: text/event-stream; charset=utf-8
Cache-Control: no-cache, no-store
X-Accel-Buffering: no
```

连接建立后服务端**先推一条全量 `snapshot`**，之后只推增量；每 15 秒发一条心跳注释行（`: ping`，零数据载荷）保持连接活性。断线时 EventSource 按 `retry: 2000` 自动重连，重连同样先拿全量快照再进增量，页面状态不会错位。

#### 2. 三类事件

| 事件 | 触发时机 | 载荷 |
| --- | --- | --- |
| `snapshot` | 连接建立 / 断线重连 | 全量：当前 token 样本 + 系统指标 + 曲线窗口长度 |
| `token` | 出现新的速率样本 | 当前样本（模型、输出/思考 token、速率、TTFT、耗时、采样时刻） |
| `history-append` | 曲线历史新增一点 | 单点增量：`completedAt` + `tokPerSec` |
| `sys` | 每 5 秒 | CPU / 内存 / 核数 / 开机时长 / 平台 |

无数据变化时通道上**只有心跳注释行**——空闲大屏不再产生任何周期性轮询请求。

#### 3. 页面消费与降级

`index.html` 用 `EventSource` 订阅，按事件类型**局部更新** DOM 与 canvas；`setInterval` 只保留时钟。不支持 EventSource 的老浏览器自动回退到原有的 REST 轮询（`/api/token-rate` + `/api/metrics`），两条 REST 端点原样保留给第三方集成。

#### 4. 单次采集、多端复用

服务端只有一条 1 秒的采集 tick：一次数据库读取 + 一次指标采样，扇出给所有 SSE 客户端。N 个浏览器标签页不再意味着 N 倍的轮询与查询。

### 渲染层：脏标记重绘 + 值不变不写 DOM

- **canvas 脏标记**：仅在收到新样本（`history-append` / `token`）或窗口 `resize` 时重绘速率曲线，以「最后样本时间戳」判脏；连续多个事件在同一帧内只画一次（rAF 合并）。
- **DPR 缓存**：`devicePixelRatio × CSS 尺寸` 一致就复用现有 canvas 缓冲，只有不一致才重置——拖动窗口、切换显示器不再反复重建位图。
- **DOM 写入守卫**：所有文本节点写入前先比对 `textContent`，值不变就不写，避免无意义的样式重算与布局抖动。
- **CPU 采样缓存**：`sampleCpuPercent()` 内含 250ms 睡眠，在 5 秒窗口内缓存复用；SSE 系统指标推送间隔随之放宽到 5s。

### 数据层：预编译语句 + 索引自检 + 耗时预算

#### 1. 统一只读访问层 `scripts/lib/usage-db.mjs`

按最新 `turn_id` 圈定本轮、窗口历史、会话累计等查询全部收敛到一个只读连接上，按 SQL 文本缓存 `node:sqlite` 的 `StatementSync`——同一进程内（如 Stop 钩子的 5 次重试循环）**不再重复 `db.prepare()`**。统计口径、字段名、守卫条件与 V2.1.0 完全一致，旧库缺 `turn_id` 列时依旧优雅降级。

#### 2. 建议索引

插件只以只读方式连接，不能代客户端建索引，因此把建议索引与 `EXPLAIN QUERY PLAN` 自检做进代码（`SUGGESTED_INDEXES` / `indexHints()`），doctor 检出全表扫描时提示用户酌情执行：

```sql
CREATE INDEX IF NOT EXISTS idx_model_usage_session_completed
  ON model_usage(session_id, completed_at DESC);

CREATE INDEX IF NOT EXISTS idx_model_usage_status_completed
  ON model_usage(status, completed_at DESC);
```

在只读连接上执行失败（无写权限）不会阻断任何流程。2 万行夹具实测：建索引前 6 条查询全部走全表扫描，建索引后 0 条全表扫描、全部 `USING INDEX`。

#### 3. 钩子耗时诊断日志

新增零依赖模块 `scripts/lib/perf-log.mjs`：对钩子单次 DB 读取计时，追加写入本地 `~/.zcode/tps-monitor.perf.log`（JSONL，超 128KB 自动截断保尾）。单次读取预算 **50ms**，超预算标记 `overBudget`。写入失败一律静默——诊断日志绝不能影响钩子本身。

#### 4. doctor 新增 perf 节

`/tps-doctor`（`--json`）的返回中新增 `perf` 对象，只读信息节、不影响通过与否：

| 字段 | 含义 |
| --- | --- |
| `budgetMs` | 单次 DB 读取预算（50） |
| `lastKind` / `lastDbMs` / `lastTs` | 最近一次钩子读取的类型、耗时、时刻 |
| `p50DbMs` / `p95DbMs` / `maxDbMs` | 最近 200 次读取的耗时分位 |
| `overBudget` | 超预算次数 |
| `dbFile` / `dbBytes` | usage 库路径与文件大小 |
| `logFile` | 诊断日志路径 |
| `fullScans` | 走全表扫描的查询清单 |

### 悬浮条：轮询放宽 + 跳过无变化更新

`overlay.ps1` 轮询间隔由 1s 放宽到 **2s**（速率数字 2s 一跳肉眼无差），主题采样改为按墙上时钟 5s 一次（不再每 tick 读配置文件），速率文本与统计文本**无变化时跳过 WPF 元素更新**。顺带修复了脚本里一处预存的 PowerShell 解析错误（`0x20 | 0x40 | 0x80 | 0x100` 作为赋值右值不被解析，已改为 `-bor`）——在此之前这个悬浮条脚本根本无法运行。

### 性能指标

| 指标 | 数值 |
| --- | --- |
| 空闲大屏周期性轮询请求 | **0**（仅 15s 心跳注释行，零数据载荷） |
| 稳态增量包大小 | **< 1KB**（`token` / `history-append` 帧，实测数百字节） |
| 2 万行 usage 库 `queryTurn` 耗时 | P95 ≈ **5ms**（预算 50ms） |
| 建议索引效果 | 全表扫描 6 → **0** |
| CPU 百分比采样 | 5s 窗口缓存（内含 250ms 睡眠，不再每次推送都采样） |
| SSE 系统指标推送间隔 | **5s** |
| 悬浮条轮询间隔 | **2s**，空载 CPU 相比 1s 轮询减半 |
| 单元测试 | **38** 条全绿（新增性能断言 12 条） |

空闲页面 CPU 目标 < 1%、Stop 钩子 P95 < 50ms 且超预算可被 `/tps-doctor` 检出——后两者由 `test/perf.test.mjs` 的断言与 doctor perf 节分别保证。

### 安全与兼容

- 全部实现仍为 Node 内置能力（`node:http` / `node:sqlite`），**core 零 npm 依赖**，无任何网络上报，数据全部留在本机。
- 配置字段只增不删：V2.2.0 没有新增配置项，旧配置文件行为与 V2.1.0 完全一致。
- MCP 返回结构不变；`/api/token-rate`、`/api/metrics`、`/api/config` 三个既有端点行为不变。
- 钩子速率计算逻辑与输出格式不变；诊断日志写入失败静默，不改变钩子任何可观测行为。

## English

V2.1.0 turned the dashboard into a customizable liquid-glass panel. V2.2.0 removes three fixed overheads on top of it — **useless polling in the transport layer, full repaints in the render layer, and inefficient SQL in the data layer**. Every optimization lives inside the existing pipeline: the hooks' rate math and output format are untouched, `/tps` and `/tps-doctor` behave as before (only `doctor --json` gains a perf section), MCP return structures are unchanged, and config fields are additive only.

### Transport: SSE push instead of interval polling

#### 1. `GET /api/events`

A new SSE endpoint, implemented with pure `node:http` and **zero third-party dependencies**:

```text
GET /api/events
Content-Type: text/event-stream; charset=utf-8
Cache-Control: no-cache, no-store
X-Accel-Buffering: no
```

On connect the server pushes a **full `snapshot` first**, then increments only; every 15 seconds it sends a heartbeat comment line (`: ping`, zero data payload) to keep the connection alive. On disconnect EventSource reconnects per `retry: 2000` and again receives a full snapshot before resuming increments, so page state never drifts.

#### 2. Three event types

| Event | When | Payload |
| --- | --- | --- |
| `snapshot` | connect / reconnect | Full: current token sample + system metrics + curve window length |
| `token` | a new rate sample appears | Current sample (model, output/thinking tokens, rate, TTFT, generation time, sampling time) |
| `history-append` | the curve gains a point | Single-point increment: `completedAt` + `tokPerSec` |
| `sys` | every 5 seconds | CPU / memory / cores / uptime / platform |

With no data changes the channel carries **heartbeat comment lines only** — an idle dashboard no longer issues any periodic polling request.

#### 3. Page consumption and fallback

`index.html` subscribes with `EventSource` and updates the DOM and canvas **partially** by event type; `setInterval` is kept for the clock only. Browsers without EventSource fall back to the original REST polling (`/api/token-rate` + `/api/metrics`), and both REST endpoints remain for third-party integrations.

#### 4. One collection tick, many consumers

The server runs a single 1-second collection tick: one database read plus one metrics sample, fanned out to every SSE client. N browser tabs no longer mean N times the polling and querying.

### Render: dirty-flag redraw + value-guarded DOM writes

- **Canvas dirty flag**: the rate curve is redrawn only when a new sample arrives (`history-append` / `token`) or the window is resized, using the last sample timestamp as the dirty mark; multiple events in the same frame coalesce into a single draw (rAF).
- **DPR cache**: the existing canvas buffer is reused while `devicePixelRatio × CSS size` matches, and is only reset on mismatch — dragging the window or moving between monitors no longer rebuilds bitmaps repeatedly.
- **DOM write guard**: every text-node write compares `textContent` first and skips the write when the value is unchanged, avoiding pointless style recalculation and layout thrash.
- **CPU sampling cache**: `sampleCpuPercent()` sleeps 250ms internally and is now cached for a 5-second window; the SSE system-metrics cadence is relaxed to 5s accordingly.

### Data: prepared statements + index self-check + read budget

#### 1. Unified read-only access layer `scripts/lib/usage-db.mjs`

Turn scoping by the latest `turn_id`, window history, and session aggregates all converge onto a single read-only connection that caches `node:sqlite` `StatementSync` objects by SQL text — within one process (such as the Stop hook's five retries) **`db.prepare()` is no longer called repeatedly**. Statistics semantics, field names, and guard conditions are identical to V2.1.0, and old databases without the `turn_id` column still degrade gracefully.

#### 2. Suggested indexes

Because the plugin connects read-only it cannot create indexes on the client's behalf, so the suggested indexes and an `EXPLAIN QUERY PLAN` self-check are shipped in code (`SUGGESTED_INDEXES` / `indexHints()`), surfaced by doctor when a full scan is detected:

```sql
CREATE INDEX IF NOT EXISTS idx_model_usage_session_completed
  ON model_usage(session_id, completed_at DESC);

CREATE INDEX IF NOT EXISTS idx_model_usage_status_completed
  ON model_usage(status, completed_at DESC);
```

Failing to run these on a read-only connection never blocks anything. Measured on a 20,000-row fixture: all 6 queries did a full table scan before the indexes and 0 after, with every plan showing `USING INDEX`.

#### 3. Hook read-timing diagnostic log

A new zero-dependency module `scripts/lib/perf-log.mjs` times each hook's single database read and appends it to a local `~/.zcode/tps-monitor.perf.log` (JSONL, auto-truncated above 128KB). The per-read budget is **50ms**; over-budget reads are flagged `overBudget`. Every write failure is silent — a diagnostic log must never affect the hook itself.

#### 4. Doctor gains a perf section

`/tps-doctor` (`--json`) now returns a `perf` object: a read-only information section that never affects the pass/fail verdict:

| Field | Meaning |
| --- | --- |
| `budgetMs` | Per-read DB budget (50) |
| `lastKind` / `lastDbMs` / `lastTs` | Type, duration, and timestamp of the most recent hook read |
| `p50DbMs` / `p95DbMs` / `maxDbMs` | Read-time quantiles over the last 200 samples |
| `overBudget` | Number of over-budget reads |
| `dbFile` / `dbBytes` | Usage DB path and file size |
| `logFile` | Diagnostic log path |
| `fullScans` | Queries doing a full table scan |

### Overlay: relaxed polling + skip unchanged updates

`overlay.ps1` relaxes its poll interval from 1s to **2s** (a 2s step is visually indistinguishable for a rate number), samples the theme on a 5-second wall clock instead of every tick, and **skips WPF element updates when the rate and summary texts are unchanged**. Along the way it fixes a pre-existing PowerShell parse error (`0x20 | 0x40 | 0x80 | 0x100` as an assignment right-hand side, now `-bor`) — before that fix the overlay script could not run at all.

### Performance figures

| Metric | Value |
| --- | --- |
| Periodic polling requests on an idle dashboard | **0** (15s heartbeat comment lines only, zero data payload) |
| Steady-state increment packet size | **< 1KB** (`token` / `history-append` frames, a few hundred bytes measured) |
| `queryTurn` on a 20,000-row usage DB | P95 ≈ **5ms** (budget 50ms) |
| Suggested-index effect | Full scans 6 → **0** |
| CPU percentage sampling | Cached in a 5s window (contains a 250ms sleep, no longer sampled per push) |
| SSE system-metrics cadence | **5s** |
| Overlay poll interval | **2s**, halving idle CPU versus 1s polling |
| Unit tests | **38** passing (12 new performance assertions) |

The targets "idle page CPU < 1%" and "Stop-hook P95 < 50ms with over-budget reads detectable by doctor" are covered by the assertions in `test/perf.test.mjs` and doctor's perf section respectively.

### Security and compatibility

- Everything is still Node built-ins (`node:http` / `node:sqlite`): the **core has zero npm dependencies**, nothing is reported over the network, and all data stays on the local machine.
- Config fields are additive only: V2.2.0 adds no config field, so old config files behave exactly as in V2.1.0.
- MCP return structures are unchanged; `/api/token-rate`, `/api/metrics`, and `/api/config` behave as before.
- Hook rate math and output format are unchanged; diagnostic-log write failures are silent and alter no observable hook behavior.

### Version

- New zero-dependency modules: `scripts/lib/usage-db.mjs` (read-only access layer + prepared statements + index self-check), `scripts/lib/sse.mjs` (SSE wire format), `scripts/lib/perf-log.mjs` (read timings).
- `marketplace.json`, `.zcode-plugin/plugin.json`, and `.claude-plugin/plugin.json` all bumped to **2.2.0**.
- New `test/perf.test.mjs` (12 performance assertions); unit tests grow from **26 to 38**.
- README (Chinese / English) gains the SSE real-time push description and a performance-figures table; `docs/releases/v2.2.0.md` (this file) is the bilingual release note.
