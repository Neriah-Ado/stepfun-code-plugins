## 中文

V2.2.0 之后，浏览器大屏已经是零轮询、脏标记重绘的高效面板。V2.3.0 在此之上补上**桌面形态**：一个可选的跨平台 Electron 客户端——仪表盘主窗口、透明置顶悬浮条、托盘菜单、开机自启与自动更新，并打通三平台打包流水线。

关键约束：**插件本体一动不动**。hooks / scripts / mcp / commands / dashboard server.mjs 依旧零 npm 依赖、纯 Node 内置能力，钩子速率计算与输出格式、`/tps`、`/tps-doctor`、MCP 返回结构、浏览器大屏功能全部保持原样。Electron 相关代码全部隔离在 `electron/` 与**工作区级**根 `package.json` 里，插件目录内不新增 package.json / node_modules；桌面客户端是独立分发物，**不进插件市场**。所有数据仍只在本机。

### 架构：复用插件核心，而不是复制一份

桌面端没有另起一套数据通路：

| 层 | 桌面端实现 | 与插件本体的关系 |
| --- | --- | --- |
| 数据 | 主进程调用 `scripts/lib/collect-core.mjs` / `scripts/token-rate.mjs` | **同一份代码**，无副本 |
| 大屏 | 主进程内嵌 `dashboard/server-core.mjs` 工厂，随机端口绑 127.0.0.1 | **同一份 index.html + 同一条 SSE** |
| 外观 | `scripts/lib/config.mjs` 读写 `~/.zcode/tps-monitor.config.json` | **同一份配置**，与大屏互通 |
| 桌面状态 | `~/.zcode/tps-monitor.desktop.json` | 独立文件，不污染插件配置节 |

主进程以 `port: 0`（随机端口）、`idleExitMin: 0`、`writePidFile: false` 启动内嵌大屏服务，然后 `loadURL` 加载它渲染出的**同一份 index.html**。也就是说桌面端看到的页面、SSE 推送、配置抽屉与浏览器里完全一致；桌面端只是多了一枚进程、两枚按钮和一枚托盘图标。

#### 目录结构

```text
electron/
  main.mjs            主进程:窗口 / 托盘 / 自启 / 自动更新 / IPC
  preload.cjs         预加载:contextBridge 暴露白名单 API
  renderer/
    overlay.html      悬浮条渲染层(透明、可拖、悬停展开)
  lib/
    overlay-payload.mjs  悬浮条数据载荷(纯函数,可单测)
    collect-loop.mjs     悬浮条采集循环(可注入 queryFn)
    state-store.mjs      窗口位置/开关持久化(纯函数 + 原子写)
  build/
    make-icons.mjs   纯 Node 生成 ICO / ICNS / PNG 图标
    icons/            生成产物
package.json          工作区级(electron / electron-builder 为 devDependency)
electron-builder.yml  三平台打包配置
.github/workflows/release.yml   标签触发三平台构建流水线
```

### 主窗口

- 加载内嵌大屏服务渲染的 index.html；尺寸、位置、置顶状态持久化，重启后恢复。
- 关闭按钮 = 最小化到托盘（进程不退出，悬浮条继续刷新）。
- 页头新增两枚**桌面专属按钮**（`html.tps-electron` 下才显示，浏览器打开完全不可见）：
  - **📌 置顶**：切换主窗口 always-on-top，状态由主进程广播同步。
  - **▣ 悬浮条**：显示 / 隐藏悬浮条，托盘与按钮状态互通。
- 主题跟随系统（`theme: system` 与浏览器大屏同语义）。

### 悬浮条

无边框、透明、置顶的小窗，只做一件事：随时可见的**当前 tok/s**。

| 能力 | 实现 |
| --- | --- |
| 透明 | `transparent: true` + `backgroundColor: "#00000000"`，页面背景全透明，仅卡片有玻璃底 |
| 置顶 | `alwaysOnTop: true` + `setAlwaysOnTop(true, "floating")`，并 `setVisibleOnAllWorkspaces` |
| 可拖拽 | 整卡 `-webkit-app-region: drag`，按钮区 `no-drag`；位置/尺寸落盘 |
| 点击穿透 | `setIgnoreMouseEvents(on, { forward: true })`——穿透时点击落到下层窗口，但 `mousemove` 仍送达，悬停展开不受影响 |
| 悬停详情 | 展开区显示首字延迟（TTFT）、近 N 次均速、累计 token 与迷你 sparkline；保持左上角锚点只增高，并夹紧在工作区内 |
| 数据 | 主进程 1s 采集循环经 IPC 推送（`queryFn` 每次重新解析当前会话），**不连 HTTP**；查询抛错回退占位载荷，循环不崩 |

悬浮条的位置、可见性、点击穿透开关都存在 `~/.zcode/tps-monitor.desktop.json`；任何损坏或越界值都被夹紧/回落默认，**绝不让桌面端起不来**。

### 托盘、开机自启、自动更新

托盘菜单六项：**显示/隐藏悬浮条**、**打开仪表盘**、**主窗口置顶**（复选）、**悬浮条点击穿透**（复选）、**开机自启**（复选）、**退出**。左键单击托盘图标切换主窗口显隐。

- **开机自启**：`app.setLoginItemSettings({ openAtLogin })`，仅在打包后生效（开发模式跳过，避免污染开发机）。
- **自动更新**：`electron-updater` 对接 GitHub Releases，`autoDownload` + 退出时安装，启动时 `checkForUpdatesAndNotify()`。`electron-updater` 因此必须是**运行依赖**（electron-builder 的 asar 不含 devDependencies）。
- **单实例**：`requestSingleInstanceLock`，第二个实例启动时聚焦已有窗口。

### 三平台打包

`npm run icons` 用纯 Node 复用插件现有 SDF 图标生成器，组装 ICO（16/32/48/256）与 ICNS（16/32/64/128/256/512）容器——不引入任何图片处理依赖。

| 平台 | 目标 | 命令 |
| --- | --- | --- |
| Windows | NSIS 安装包（x64 / arm64）+ portable（x64） | `npm run dist:win` |
| macOS | dmg（x64 / arm64） | `npm run dist:mac` |
| Linux | AppImage（x64 / arm64） | `npm run dist:linux` |

`.github/workflows/release.yml` 在推送 `v*` 标签（或手动触发）时：先跑 `node --test` 全量单测，通过后三平台矩阵并行构建，产物连同 `latest*.yml` 与 blockmap 一起上传为 GitHub Release 附件，`electron-updater` 即可发现。手动触发时默认 `--publish never`，只出产物不发版。

> **体积提示**：产物包含完整 Electron 运行时，属于百 MB 量级（NSIS 安装包与 portable 通常在 80–100 MB 上下，dmg / AppImage 与之相当或略大；具体以 Release 附件为准）。这是跨平台桌面客户端的固有成本——若只想要 Windows 上的一枚悬浮条，`dashboard/overlay.ps1` 仍是零安装的单文件选择。

### overlay.ps1：退役路径

`overlay.ps1` **保留并标注**为「无 Electron 时的轻量替代」：零安装、单文件、仅 Windows，覆盖悬浮条的基础能力。自 V2.3.0 起它只做维护、**不再新增功能**；需要跨平台（Windows / macOS / Linux）、托盘、开机自启、自动更新时，请改用 Electron 客户端。

## English

After V2.2.0 turned the browser dashboard into a zero-polling, dirty-flag-redrawn panel, V2.3.0 adds the **desktop form factor**: an optional cross-platform Electron client — dashboard main window, transparent always-on-top overlay, tray menu, autostart and auto-update — plus a three-platform packaging pipeline.

The key constraint: **the plugin itself does not move**. hooks / scripts / mcp / commands / dashboard server.mjs keep zero npm dependencies and pure Node built-ins; hook rate math and output format, `/tps`, `/tps-doctor`, MCP return structures and the browser dashboard are all unchanged. Every Electron-related line lives in `electron/` and the **workspace-level** root `package.json`; no package.json or node_modules is added inside the plugin directory, and the desktop client is an independent distribution artifact that is **not in the plugin marketplace**. All data stays on the local machine.

### Architecture: reuse the plugin core, don't fork it

The desktop client invents no second data path:

| Layer | Desktop implementation | Relation to the plugin |
| --- | --- | --- |
| Data | Main process calls `scripts/lib/collect-core.mjs` / `scripts/token-rate.mjs` | **The same code**, no fork |
| Dashboard | Main process embeds the `dashboard/server-core.mjs` factory on a random port bound to 127.0.0.1 | **The same index.html, the same SSE** |
| Appearance | `scripts/lib/config.mjs` reads/writes `~/.zcode/tps-monitor.config.json` | **The same config**, interoperable with the dashboard |
| Desktop state | `~/.zcode/tps-monitor.desktop.json` | A separate file, no pollution of the plugin config |

The main process starts the embedded dashboard with `port: 0` (random port), `idleExitMin: 0`, `writePidFile: false`, then `loadURL`s the **same index.html** it serves. The desktop app therefore shows exactly the page, SSE stream and settings drawer the browser shows; it merely adds a process, two buttons and a tray icon.

#### Layout

```text
electron/
  main.mjs            main process: windows / tray / autostart / auto-update / IPC
  preload.cjs         preload: contextBridge with an allowlisted API
  renderer/
    overlay.html      overlay renderer (transparent, draggable, hover to expand)
  lib/
    overlay-payload.mjs  overlay payload (pure, unit-tested)
    collect-loop.mjs     overlay collection loop (injectable queryFn)
    state-store.mjs      window bounds / toggles persistence (pure + atomic write)
  build/
    make-icons.mjs   pure-Node ICO / ICNS / PNG icon generation
    icons/            generated artifacts
package.json          workspace level (electron / electron-builder as devDependencies)
electron-builder.yml  three-platform packaging config
.github/workflows/release.yml   tag-triggered three-platform pipeline
```

### Main window

- Loads the index.html served by the embedded dashboard; size, position and always-on-top state persist across restarts.
- The close button **minimizes to tray** (the process stays alive and the overlay keeps updating).
- Two **desktop-only buttons** appear in the header (visible only under `html.tps-electron`, entirely hidden in a browser):
  - **📌 Pin**: toggles main-window always-on-top, state broadcast by the main process.
  - **▣ Overlay**: shows / hides the overlay, kept in sync with the tray.
- The theme follows the system (`theme: system`, same semantics as the browser dashboard).

### Overlay

A frameless, transparent, always-on-top window that does one thing: keep the **current tok/s** visible at all times.

| Capability | Implementation |
| --- | --- |
| Transparency | `transparent: true` + `backgroundColor: "#00000000"`; the page is fully transparent, only the card has a glass background |
| Always on top | `alwaysOnTop: true` + `setAlwaysOnTop(true, "floating")`, plus `setVisibleOnAllWorkspaces` |
| Draggable | Whole card `-webkit-app-region: drag`, buttons `no-drag`; position/size persisted |
| Click-through | `setIgnoreMouseEvents(on, { forward: true })` — clicks fall through to the window below while `mousemove` still arrives, so hover-expand keeps working |
| Hover details | Expanded area shows TTFT, N-sample average, cumulative tokens and a mini sparkline; keeps the top-left anchor and grows height only, clamped into the work area |
| Data | A 1s collection loop in the main process pushes payloads over IPC (the `queryFn` re-resolves the followed session every tick) — **no HTTP**; query errors fall back to a placeholder payload and never crash the loop |

Overlay position, visibility and the click-through toggle live in `~/.zcode/tps-monitor.desktop.json`; any corrupt or out-of-range value is clamped or falls back to a default — **a broken state file must never prevent the desktop app from starting**.

### Tray, autostart, auto-update

The tray menu has six items: **show/hide overlay**, **open dashboard**, **main window on top** (checkbox), **overlay click-through** (checkbox), **open at login** (checkbox), **quit**. Left-clicking the tray icon toggles the main window.

- **Autostart**: `app.setLoginItemSettings({ openAtLogin })`, applied only when packaged (skipped in dev mode so the development machine is not touched).
- **Auto-update**: `electron-updater` against GitHub Releases with `autoDownload` and install-on-quit, calling `checkForUpdatesAndNotify()` at startup. `electron-updater` is therefore a **runtime dependency** (electron-builder's asar excludes devDependencies).
- **Single instance**: `requestSingleInstanceLock`; a second launch focuses the existing window.

### Three-platform packaging

`npm run icons` reuses the plugin's existing SDF icon generator in pure Node and assembles ICO (16/32/48/256) and ICNS (16/32/64/128/256/512) containers — no image-processing dependency is introduced.

| Platform | Targets | Command |
| --- | --- | --- |
| Windows | NSIS installer (x64 / arm64) + portable (x64) | `npm run dist:win` |
| macOS | dmg (x64 / arm64) | `npm run dist:mac` |
| Linux | AppImage (x64 / arm64) | `npm run dist:linux` |

`.github/workflows/release.yml` runs on `v*` tags (or manual dispatch): it runs the full `node --test` suite first, then builds on a three-platform matrix in parallel and uploads the artifacts together with `latest*.yml` and blockmaps as GitHub Release assets for `electron-updater` to find. Manual dispatch defaults to `--publish never`, producing artifacts without publishing a release.

> **Size note**: artifacts bundle the full Electron runtime and land in the hundreds of MB (an NSIS installer or portable build is typically in the 80–100 MB range, with dmg / AppImage comparable or slightly larger; see the Release assets for exact figures). That is the inherent cost of a cross-platform desktop client — if all you want is a Windows overlay, `dashboard/overlay.ps1` remains a zero-install single-file option.

### overlay.ps1: retirement path

`overlay.ps1` is **kept and annotated** as the "lightweight alternative when Electron is unavailable": zero install, single file, Windows only, covering the overlay's basic capabilities. From V2.3.0 on it is maintained only and gains **no new features**; for cross-platform (Windows / macOS / Linux), tray, autostart and auto-update, use the Electron client.

### Security and compatibility

- **The plugin core stays zero-npm-dependency**: `test/desktop.test.mjs` contains a scan assertion that walks every `.mjs/.cjs/.js` under `plugins/zcode-tps-monitor`; any import outside `node:` / relative paths, any `require("pkg")`, or a package.json / node_modules appearing inside the plugin turns the suite red.
- Hooks, `/tps`, `/tps-doctor` and MCP behavior are untouched; the browser dashboard (SSE + settings drawer) works as before, and the desktop buttons are `display: none` outside Electron.
- Config fields are additive only: this version adds no `appearance` field, so old configs behave identically on desktop and in the browser; desktop-only state goes to its own file.
- **All data stays local**: the embedded server binds 127.0.0.1 only and the main process initiates no external request (the only network behavior is `electron-updater` checking GitHub Releases when packaged, which can be disabled).
- All Electron dependencies are confined to the workspace-level `package.json`; `marketplace.json` never references the desktop client.
