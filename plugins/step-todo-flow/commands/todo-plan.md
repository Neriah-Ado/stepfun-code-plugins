# /todo-plan — 需求拆分

<!-- PLAN-RULES-START -->
```json
{
  "limit": "最多 7 条；拆不出来说明需求过大，建议先做技术调研再重拆",
  "entry": "每条 = 动作短语 + 可验证的完成标准（如「登录接口返回 401 路径有测试覆盖」）",
  "forbidden": "禁止「继续完善」「优化体验」等不可验收措辞；含糊点在条目后括号标注 待澄清",
  "write": "拆分结果先整体展示，用户确认后经 /todo 的 diff 流程写入"
}
```
<!-- PLAN-RULES-END -->

## 流程

1. 理解需求，按「可独立验证」切分为 ≤ 7 条。
2. 逐条检查：有没有完成标准？能不能被别人一眼判定做没做完？不满足就重写。
3. 整体展示（含每条验收标准与待澄清标注），确认后写入 TODO.md。
4. 待澄清问题单独列在结尾，提示优先澄清后再开工对应条目。

## 输出格式

条目清单（编号 / 描述 / 验收标准）→ 待澄清问题 → 写盘结果。
